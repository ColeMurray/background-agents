This page explains what an agent harness is, how the available harnesses differ, and what to expect
from subscription-backed harnesses.

## One harness per session

The agent harness is the coding agent that executes a session. OpenCode, Claude Agent, and Codex run
inside a sandbox. The optional Pi Durable harness runs in a dedicated Cloudflare Durable Object
without provisioning a sandbox. Every session runs on exactly one harness, chosen when the session
is created and fixed for its lifetime, like the base branch.

- Child sessions inherit their parent's harness.
- An automation carries a harness for the sessions it creates.
- Sessions started by Linear run on the harness chosen in Settings › Integrations › Linear, globally or per repository (OpenCode by default). A model the chosen harness cannot run, such as one from a `model:gpt-*` label, is refused with an error activity and no coding session. Choose a compatible `model:*` label, user preference, or default model, or change the integration harness, then delegate again.
- Sessions started by Slack run on the harness the user chose in the Slack app's Home tab, else the one chosen in Settings › Integrations › Slack (OpenCode by default). A request whose model that harness cannot run, such as one from `!model openai/gpt-5.4` or an App Home preference, is refused rather than started on OpenCode. A Slack thread keeps its session's harness.
- Sessions started by GitHub run on the harness chosen in Settings › Integrations › GitHub, globally or per repository (OpenCode by default). A model the chosen harness cannot run is refused with a reply on the PR and no session. Retry a mention with a compatible `!model`, update the default model, or change the integration harness.
- OpenCode is the default harness.

All three integrations preserve a supported selected harness rather than silently falling back to OpenCode. Pi Durable is not yet supported by GitHub or Linear because those flows require local diff, mutation, and publication tools; settings writes reject Pi, and legacy Pi values resolve to OpenCode. For GitHub and Linear, explicitly selecting a restricted harness such as Claude Agent requires a compatible default model at the same settings level (global or repository). Omitted repository harness and model fields inherit individually. Save validation checks each explicit level, not the merged global/repository pair; cross-level mismatches are refused at launch. See [GitHub settings](/integrations/github#repository-overrides) and [Linear settings](/integrations/linear).

Existing GitHub and Linear settings that select Claude Agent without a default model are not automatically migrated. They remain readable, and rejected saves leave them unchanged. Before saving any edits, including unrelated settings, an administrator must open **Settings > Integrations > GitHub** or **Linear** and choose a compatible Anthropic default model at every global or repository level that explicitly selects Claude Agent. A global model alone does not repair an explicit repository harness override. Alternatively, switch that level to OpenCode, or remove the repository harness override to inherit global settings.

Harnesses project their output into the same session timeline and completion contract. Operators may
enable a read-only or bounded writable durable scratch workspace for Pi. A terminal, local Git
checkout, network access, and sandbox processes remain unavailable.

## Pi Durable sessions

Pi Durable is an experimental, deployment-level opt-in. It uses Pi Durable and Cloudflare's
`PiHarness` to persist the conversation, submissions, and model tasks in `PiSessionDO` SQLite. Pi's
lifecycle job resumes unfinished model work after eviction, and a separate durable projection job
settles the owning OpenInspect session.

The initial integration supports only a connected OpenAI Codex subscription account. API-key mode,
legacy scoped OAuth, and the optional Claude subscription plugin are rejected. OpenInspect remains
the credential authority: Pi receives a short-lived access token in memory and never stores the
real refresh token.

The runtime installs Pi extensions before opening the durable harness:

- replay-safe repository list/read tools use a session-scoped authorization check and a commit SHA
  pinned on first open;
- managed skills come from the session's immutable skill manifest;
- a replay-safe foreground subagent owns its child Pi conversation and cannot recursively delegate.

Repository-backed web, Slack, and automation sessions are supported for remote read/analysis work
without a checkout or sandbox. In personal or staging deployments that explicitly accept Cloudflare
Computer's preview status, `PI_WORKSPACE_MODE=read_only` gives Pi a durable credential-free
`/workspace/scratch` area with `read`, `ls`, `find`, and `grep`; `writable` also provides bounded
`write`, `edit`, and `delete`. Writable scratch files have an 8 MiB and 1,000-entry aggregate quota,
mutations run one at a time, interrupted mutations are not replayed, and neither `/workspace/scratch`
nor its `/workspace` container can be deleted. Durable policy records contain metadata only; write and edit contents are redacted from
projected timeline events. The scratch area is not a
checkout or repository authority. Pi still has no shell, Git mutation, pull-request creation,
browser automation, memory mutation, Code Mode, or MCP client/OAuth integration. Image attachments
are rejected. GitHub review/comment and Linear issue integrations must use another harness until
their diff, mutation, and publication tools exist. See the operator rollout in the repository's
`docs/GETTING_STARTED.md`.

Deployments must also set `pi_computer_preview_acknowledged = true` (or the deployment Actions
variable `PI_COMPUTER_PREVIEW_ACKNOWLEDGED=true`); Terraform plan and apply reject read-only,
writable, or repository-editing activation without that explicit acknowledgement. Repository
overlays are pinned session data: authorized participants can keep reading a complete overlay after
provider or grant revocation, while new materialization, repair, and external publication remain
blocked. Missing, modified, or unexplained unchanged files fail closed. Deleting or fencing the
session purges the pinned data. Successful repository mutations are not rolled back by a diff-service
outage; they report projection pending and a durable coalesced outbox retries while retaining the
last published bundle.

The workspace mode is snapshotted durably when a Pi session first opens. Deployment flag changes
apply to later sessions and do not silently change an existing session's capabilities after eviction.

Pi reports token usage, but Codex subscription requests do not expose a provider dollar charge.
Dollar cost totals and dollar budget enforcement are therefore unavailable, matching the native
Codex harness.

## Comparison

|                                | OpenCode                                                             | Claude Agent                                                                                         |
| ------------------------------ | -------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------- |
| Models                         | Every model in the catalog                                           | Anthropic models only                                                                                |
| Anthropic authentication       | `ANTHROPIC_API_KEY` only                                             | `ANTHROPIC_API_KEY` or a connected Claude account                                                    |
| OpenAI and xAI authentication  | API key or a connected account                                       | Not applicable (cannot run those models)                                                             |
| Repository instruction files   | The repository's `.opencode/` directory and `.openinspect/setup.sh`  | Reads the repository's `CLAUDE.md` natively; loads `.claude/` settings, hooks, and agents            |
| Sub-agents                     | The `task` tool; the timeline groups a sub-agent's activity under it | The `Agent` tool; returns only when the sub-agent has finished, grouped in the timeline the same way |
| Follow-up prompts              | Queue until the running turn completes                               | Queue until the running turn completes                                                               |
| Resume after a sandbox restore | By session id                                                        | By session id                                                                                        |

<Callout type="info" title="Installation default Anthropic account">
  A default Claude account set under Settings › Accounts (provider accounts) takes effect only on
  Claude Agent sessions, including automations and Linear, Slack, and GitHub sessions configured for
  Claude Agent. OpenCode sessions, and the bot and integration sessions that run on OpenCode, keep
  using `ANTHROPIC_API_KEY`, so setting a default never breaks a session that cannot use it.
</Callout>

## Choose a harness in the composer

1. Open the model control in the new-session composer. It reads `<harness>: <model> <effort>`.
2. Choose **Agent**, then **OpenCode**, **Claude Agent**, or **Pi Durable** when the deployment advertises it. Your last choice is remembered for the next new session.
3. Choose **Model**. The list is filtered to enabled models the chosen harness can run. If none of the enabled models can run on the harness, the composer reports that no enabled models are available and blocks submission until you enable one or switch harness.
4. Choose **Effort** if the model supports it, then send your prompt.

Switching harness drops any provider authentication pin the new harness cannot honor (for example a connected Claude account selected for a session you then switch to OpenCode), so you never submit a selection the server would refuse.

Once the session exists, the **Agent** row disappears. Per-message model overrides on the session page are limited to models the harness can run; an override outside that set is rejected with an error such as `Model "openai/gpt-5.5" cannot run on the Claude Agent harness.` rather than replaced.

## Claude Agent sessions

Claude Agent runs Anthropic models through the Claude Agent SDK inside the sandbox. It is the harness that can use a connected Claude subscription instead of an API key.

<Callout type="info">
  Model availability under a Claude subscription is controlled by Anthropic. Confirm the account you
  connect can use the selected model before rolling it out broadly.
</Callout>

### How the credential reaches the sandbox

- The session's Anthropic authentication choice (a connected account or the API key) is fixed when the session is created, before any sandbox starts.
- The platform holds the credential. Nobody signs in inside a sandbox, and the token is never shown in the browser.
- On every start of the agent (fresh spawn, supervised restart, or snapshot restore), the sandbox fetches the token from the control plane and keeps it in memory only. Nothing is written to disk, so a snapshot carries no credential and a restore fetches again.
- The `claude` process sees the ordinary sandbox environment (user secrets, proxies, session context) plus exactly one Anthropic credential: the connected account's token in account mode, or `ANTHROPIC_API_KEY` in key mode, never both. OpenCode, code-server, the terminal, and user shells never see the Claude token.

Code the agent runs from Bash, and any hooks the repository's `.claude/` settings register, run as children of the `claude` process and inherit its environment. That is the same exposure as the sandbox token and user secrets under either harness.

### Tools served to the agent

OpenInspect's own tools are served to Claude Agent in-process as the `oi` MCP server:

| Tool                                                                                         | Available                                               |
| -------------------------------------------------------------------------------------------- | ------------------------------------------------------- |
| Child session tools (`spawn-child`, `send-child-prompt`, `get-child-status`, `cancel-child`) | Always                                                  |
| `upload-media`                                                                               | Always                                                  |
| `create-pull-request`                                                                        | When the session has a repository                       |
| `slack-notify`                                                                               | When agent notifications are enabled for the repository |

Session MCP servers configured under Settings › MCP Servers are passed through unchanged.

### Sub-agents

Background sub-agents are disabled. An `Agent` tool call returns only when its sub-agent has finished, and several sub-agents launched in one message still run concurrently. This keeps a turn from ending before delegated work is done. As a second guard, the harness ignores the result of any turn it did not submit.

### Privacy settings

The harness disables the underlying agent's commit, pull request, and session-link attribution. It also disables nonessential Anthropic traffic, error reporting, feedback and surveys, and both Anthropic and OpenTelemetry usage telemetry. Model requests and OpenInspect's own per-turn cost accounting are unaffected.

### Skills and repository settings

Managed skills and the bundled skills are staged in a per-sandbox Claude configuration directory (`~/.openinspect/claude/skills`). The repository's `.claude/` settings, hooks, and agents load from the project, the same trust boundary as `.openinspect/setup.sh` and `.opencode/` under OpenCode. See [Managed skills](/configure/managed-skills).

### Cost reporting

Claude Agent reports the SDK's client-side cost estimate per turn (the running total at turn end minus the total at turn start, reset when the agent process restarts). Under a subscription the figure is informational, but a session spend limit still applies to it as configured. See [Spend limits](/sessions/spend-limits).

## When a bound Claude account changes

| Change in Settings › Accounts | Effect on sessions bound to that account                                                                                                            |
| ----------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Disable**                   | The next prompt fails before a sandbox spawns, with guidance to reconnect the account. The next start of the agent on any bound session is refused. |
| **Archive**                   | The next prompt fails with guidance to start a new session with another account or an API key. An archived account cannot be reconnected.           |
| **Reconnect**                 | The account stays active with the new credential. Bound sessions carry on, and their next agent start fetches the new token.                        |
| Recorded expiry approaching   | The account is fenced to **Reconnect required**; the next prompt fails with reconnect guidance.                                                     |

In every case a sandbox that already holds a token keeps it in memory until it exits (inactivity timeout, hard timeout, or a stop), so a turn already running finishes on the old token. To end that sooner, stop the session from the session page. A runtime authentication failure fails the prompt with reconnect guidance and posts an error event; quota and rate-limit warnings keep the account active and appear on the timeline.

## Troubleshooting

<Accordions>
  <Accordion title="The composer offers no connected Claude account">
    The Agent row is set to OpenCode. The authentication control says `OpenCode runs Anthropic on
    its API key; connected accounts are not offered.` Switch to Claude Agent before choosing the
    account.

</Accordion>
  <Accordion title='Prompt fails with "cannot use a connected anthropic account"'>
    The session's harness is OpenCode and its Anthropic authentication was set to an account. Select
    an API key for that session, or create a new session on Claude Agent.

</Accordion>
  <Accordion title="A Claude Agent prompt fails asking you to reconnect the account">
    The bound account is disabled, fenced for expiry, or hit an authentication failure at runtime.
    Reconnect it under Settings › Accounts (provider accounts) and send the prompt again. If the
    account is archived, start a new session with another account or an API key.

</Accordion>
</Accordions>
