The Templates gallery pre-fills the Create Automation form with a working trigger and instructions so you can start from an idea instead of a blank form.

![The Automation templates gallery with Popular, Code Review, Security, Incidents, and Data and Research categories](/images/automations/automation-templates.webp "The templates gallery. Each card names its trigger and what it produces, with an Add button.")

## Opening the gallery

Open **Automations** in the sidebar and click **Browse templates** (the page is Automations › Templates). The gallery is available to anyone who can create automations; Viewers are redirected back to the list.

Filter the cards by category with the buttons at the top. Each card shows the trigger type, the primary output (a pull request or a Slack post), a description, and a setup note when the template needs configuration beyond picking a repository. Click **Add** on a card to open the create form with the template applied.

## What a template pre-fills

A template fills in the **Name**, **Trigger Type**, **Instructions**, and, depending on the template, the schedule, event type, conditions, model, and reasoning effort. It never selects a repository, never sets a timezone (the form's default applies), and never creates or runs anything by itself; you still review the form and click **Create Automation**.

If a template suggests a model that is not enabled in Settings › Models, the form switches to an enabled model the harness can run.

## Customizing after choosing a template

After clicking **Add**, the create form opens with the template applied. Before saving:

1. Select the **Repository Configuration** and, for a single repository, the **Branch**. Templates never choose these for you.
2. Check the **Agent**, **Model**, and **Reasoning Effort**, and set provider authentication pins if you need them.
3. Edit the **Instructions**. Slack-posting templates name a channel such as `#security`; change it to the channel you use. Review templates assume the GitHub CLI is available in the sandbox.
4. For schedule templates, adjust the **Schedule** and **Timezone**; the default cadences are conservative to limit recurring cost.
5. For event templates, confirm the **Event Type** and add or adjust **Conditions**. The Slack template needs at least one **Slack Channel** condition before it can be saved.
6. Click **Create Automation**, then use **Trigger Now** to test.

Everything a template sets can be changed later with **Edit**, except the trigger type.

## Troubleshooting

| Symptom                                                     | Cause                                                                                                             | Fix                                                                                                         |
| ----------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------- |
| Opening the gallery sends you back to the Automations list  | Your role cannot create automations (Viewers cannot)                                                              | Ask an Owner or Administrator for the Member role; see [Workspace access](/administration/workspace-access) |
| The Slack template will not save                            | "Slack triggers require at least one Slack Channel condition."                                                    | Add a **Slack Channel** condition with the channel to watch                                                 |
| The form shows a different model than the template suggests | The suggested model is not enabled under Settings › Models, so the form picked an enabled one the harness can run | Keep the substitute, or enable the suggested model under Settings › Models and select it                    |
