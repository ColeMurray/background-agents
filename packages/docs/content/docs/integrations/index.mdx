OpenInspect sessions can be started from Slack, from a GitHub pull request, from a Linear issue, or by an automation, and every one of them is the same kind of session you would start from the web app.

![Settings, Integrations: GitHub Bot, Linear Agent, Code Server, VNC Desktop, and Slack entries](/images/integrations/integrations-list.webp "Settings › Integrations. Open an entry to configure its connection and behavior.")

## Choose an entry point

| Integration                                                       | Start work                                                                                                              | Continue                                                                                                                  | Where results appear                                                                                             | Authorization                                                                                                                 |
| ----------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------- |
| [Slack](/integrations/slack)                                      | `@mention` the bot in a channel, or send it a DM                                                                        | Reply in the same Slack thread (the mapping lasts about 7 days)                                                           | A completion reply in the thread with a **View Session** button; full output in the web session                  | Deployment-level repository access through the GitHub App installation; the bot only works in channels it was invited to      |
| [GitHub](/integrations/github)                                    | Open a non-draft pull request (auto-review), or `@mention` the bot in a PR comment or review thread                     | Not by comment: every accepted webhook starts a new session. PR Feedback Autofix can resume the session that created a PR | A review, review-thread replies, or a PR comment, all written by the agent; an eyes reaction confirms acceptance | GitHub App installation plus **Repository Scope** and **Allowed Trigger Users** (write, maintain, or admin access by default) |
| [Linear](/integrations/linear)                                    | `@mention` or assign the Linear Agent on an issue                                                                       | Follow-ups through the same active Linear Agent session                                                                   | Linear activities with **View Session** and **Pull Request** links                                               | **Repository Scope** in Linear settings; repository access comes from the source-control integration, not from Linear         |
| [Inbound webhooks and automations](/automations/inbound-webhooks) | A schedule, an inbound webhook, a GitHub event, a matching Slack channel message, or a Sentry alert fires an automation | Slack message automations continue in the triggering thread for 7 days; other triggers start a run per event              | The session in the web app; Slack message automations also post into the triggering thread                       | The automation's own conditions (for example a Slack User allowlist) and the same repository boundary as everything else      |

There are no slash commands in Slack or GitHub, and there is no browser extension. Slack requests in channels need an `@mention`, and GitHub requests need the bot's full username including `[bot]`.

## Rules every integration shares

**Installation scope is the access boundary.** Integrations see the repositories the configured GitHub App installation can reach, not a per-user list. To restrict what an integration can touch, install the GitHub App only on the intended repositories, then narrow further with the integration's **Repository Scope** setting.

**Trigger gates decide who can start work.** GitHub checks repository permission (or an explicit user list). Slack and Linear rely on channel membership and workspace access. Integrations act on behalf of a workspace user and are limited by that user's current role and by a fixed set of allowed operations, so a suspended user cannot start work through a bot and an Owner cannot administer the workspace through one.

**External text is treated as data.** Slack thread history, forwarded messages, GitHub PR titles and comments, and Linear issue content are passed to the agent as untrusted input, not as instructions. Do not put secrets in issues, comments, or Slack messages: their text reaches the agent.

**The web session is the source of truth.** Slack, GitHub, and Linear show acknowledgements, short completion summaries, and links. Live output, tool calls, file changes, artifacts, and the option to take over live in the [session page](/sessions/session-page). Sessions started by any integration or automation run on the OpenCode harness.
