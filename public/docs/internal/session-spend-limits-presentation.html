Open-Inspect / Design Review
Proposed design · August 2026

Per-session
spend limits.

A best-effort guardrail that pauses model work when OpenCode-reported session cost reaches an operator-defined limit.

Guardrail, not billing Session DO authoritative No limit by default
The gap

We measure cost.
We do not bound it.

01

Autonomy compounds

Queued follow-ups, bots, automations, and child sessions can continue unattended.

02

Current controls are indirect

Timeouts and child-count limits constrain work volume, not reported model cost.

03

The signal already exists

OpenCode reports optional cost per step; the Session DO maintains the live total.

Design at a glance

One limit. One authority.
One pause rule.

Configure

Optional USD limit through global → repository → environment sandbox settings.

Snapshot

Resolve at session creation and store the mutable effective limit in Session DO SQLite.

Enforce

After each positive finite reported step cost, compare the authoritative total.

Resume

The session owner raises or removes the live limit; queued work resumes in FIFO order.

effective limit = session max_cost_usd  ·  null = unlimited
System flow

Enforce where the total moves.

Source OpenCode

Emits optional cost and token usage on step_finish.

Transport Sandbox runtime

Forwards the event unchanged over the existing WebSocket.

Authority Session DO

Atomically increments total_cost, evaluates, and persists state.

Effect Queue + clients

Warn, stop active work, pause dispatch, and broadcast authoritative state.

D1 remains a settled-turn analytics mirror. It is never consulted for live enforcement.

Critical behavior

Pause the queue.
Preserve the work.

Exhaustion is an orthogonal session condition, not cancellation. Pending prompts remain durable and ordered.

Active prompt
Failed with a budget-specific reason; sandbox receives the existing stop command.
Pending prompts
Remain pending. Dispatch checks exhaustion at entry and again after awaited auth.
New prompts
Rejected with HTTP 409 or correlated WebSocket code BUDGET_EXHAUSTED.
Recovery
Latch, warning, failed message, stop deadline, and alarm intent commit atomically.
Live changes + permissions

The owner controls
the session limit.

Owner-only mutation

Verified human principal plus authoritative Session DO participant role check.

Set or remove

Positive USD value sets the live limit; null makes this session unlimited.

Idempotent updates

An unchanged limit is a no-op. Changed limits immediately re-evaluate warning and exhaustion.

  • Sandbox and service principals cannot raise their own limit.
  • Members can observe state but do not see mutation controls.
  • Raising above observed cost or removing the limit resumes the oldest pending prompt.
Scope boundary

Per session means
per session.

Included

OpenCode internal subtasks

They execute inside the same Open-Inspect session and contribute to the same observed total.

Separate

Open-Inspect child sessions

Each child resolves its own limit and owns a separate Session DO cost aggregate.

Must know: fan-out multiplies the boundary

An automation targeting N repositories can create N independently limited sessions. This design does not provide an invocation-wide or root-lineage budget.

Must know

Four constraints define
the promise.

01 · Best effort, not billing

step_finish is non-critical, unacknowledged, and has no deduplication key.

02 · Post-step overshoot

Cost arrives after the step. The triggering step can take observed cost above the limit.

03 · Missing cost stays unknown

Positive-token steps without cost set a visible one-way honesty flag; no price is inferred.

04 · D1 is not live authority

D1 analytics can lag. Enforcement reads only the Session DO's current aggregate and state.

Client synchronization

Authoritative state,
careful release.

Snapshots hydrate reconnects. budget_status replaces observed cost and budget state live; warning events remain durable timeline records.

Two-merge compatibility sequence

Merge 1: shared schemas + web handling, no server emission.

Merge 2: control-plane storage, emission, and enforcement.

Stale tabs

Old bundles reject unknown variants and must reload; reconnect alone does not upgrade code.

Scope discipline

Useful guardrail.
No billing platform.

No repricing

No local pricing tables, token conversion, or provider invoice matching.

No aggregate budgets

No user, workspace, automation, root-lineage, daily, or monthly spend pools.

No event-ledger rebuild

No durable step journal, acknowledgement protocol, or cost reconciliation in this feature.

No “send anyway”

Every source follows the same exhausted rule until the owner changes the limit.

No new lifecycle status

Budget state remains explicit and orthogonal to active, failed, completed, or cancelled.

No default limit

Existing deployments remain unchanged until an operator configures a limit.

Final takeaway

Bound continued work.
Tell the truth about precision.

The proposed design puts a small, durable control loop around the cost signal Open-Inspect already has: resolve a limit, compare in the Session DO, pause safely, and let the owner resume.
