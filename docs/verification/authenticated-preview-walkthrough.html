02 /

One command gets it ready.

Once the tools are installed, start the preview and keep that command running while you work.

FROM THE REPO ROOT
npm run preview -- --scenario populated --persona member --browser agent-browser

Wait for the “ready” line. It tells you the URL, browser session name, and test conversation IDs.

Needs Node 22.13+, project packages, agent-browser 0.37.0 and Chrome. No Docker is needed for the preview itself.

First-time setup & other ways to run
  • Run npm ci to install project packages.
  • Install the pinned agent-browser@0.37.0 and Chrome if they are not already there. The OpenInspect image includes them.
  • Use --browser none to start without an agent browser.
  • Use npm run test:preview for the browser tests; first install their browser with npx playwright install chromium.

The preview does not install tools for you. First-time setup may need the internet.

05 /

Easy to reset. Clear about its limits.

This is a place to check changes, not a copy of the live system.

Start fresh→Check→Stop & clear
Your work stays yours.

Separate files, test keys and browser sessions. No changes to your .env.local. One preview per checkout.

Sign-out means sign-out.

The login is loaded once, not added back on every open. A failed first login load makes you restart the preview.

Stop clears the test world.

Ctrl-C stops owned servers and browsers, then removes the temporary database and login files. Runs end after four hours.

Failures leave a clue.

A short error log stays behind with known test secrets removed. Read it before sharing. Stuck tasks are reported as failures.

Still needs a separate check

  • Signing in through real GitHub
  • A real AI model doing the work
  • A real cloud sandbox saving or waking
  • Cloud storage and live site settings

The preview uses stand-ins for outside services. The Docker check adds local container and backup proof; neither is a live-system test. No remote OpenInspect sandbox was used.

A fresh agent checked it before the PR.

It looked for weak tests, brittle code, and needless extra layers. It approved the fixes.

Setup can stop even when a request gets stuck.

New tests hold real requests open, then check that a stop or time limit cleans up.

Logout checks the other user too.

A good status code is not enough. The test checks who is still signed in and what they can open.
