# Proposal: observable and reconcilable Modal startup

Status: **review only; not implemented or deployed**. Context and evidence:
[DIV-83 diagnosis](../deployments/modal-startup-diagnosis-2026-09-16.md). Keep the existing HTTP
deadline, mandatory image verification and investigation boundary while reviewing these changes. Do
not solve an unknown provider outcome by silently extending timeouts.

| Change                     | Concrete location and behavior                                                                                                                                                                                                                                                                                                                                                                                                                                    | Focused acceptance checks                                                                                                                                                                                                                                                        |
| -------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Fence canceled generations | DIV-84's supported pending-message settlement must atomically prevent later dispatch, preserve callback identity, and revoke/retire the old sandbox generation; account for an already-connected bridge and pending-to-processing races. Integrate `ExecutionStopCoordinator`, message failure/callback services, connection admission and queue dispatch. Do not globally disable the intentional failed-start self-heal behavior without reviewing its callers. | Pending Linear + callback cancellation; duplicate cancellation; late bridge before/after commit; already-connected bridge; cancellation during auth hashing/provider return; pending-to-processing race; callback retry without duplicate completion; DO reload preserves fence. |
| Correlated startup stages  | Add sanitized start/finish/failure records around create handler entry, validation, manager import, dependency/create await and provider-ID return in `web_api.py` and `sandbox/manager.py`. Reuse trace/request/session/logical generation IDs; persist provider object ID as soon as available, before optional tunnel setup. Include function input/container IDs and SDK version when available. Do not log request/environment/token values.                 | Correlation survives failure/cancellation; separate header and body timeout evidence; no secrets in events; no false success from a late/superseded result.                                                                                                                      |
| Durable create outcome     | Add an authenticated create-operation status/settlement contract backed by durable storage and keyed by session plus generation. Persist admission before external create; support unknown-outcome reconciliation. SDK transport idempotency alone is insufficient for repeated HTTP calls. Evaluate a stable Modal name/tag and provider deduplication semantics under the pinned SDK; a tag added after create cannot close the lost-ID window.                 | Response lost after allocation, crash before ID persistence, duplicate HTTP delivery, concurrent cancellation, superseded generation and provider outage; retries never create a second live worker or dispatch a terminal prompt.                                               |
| Exact-object cleanup       | Extend the interactive Modal provider's supported termination/reconciliation capability only after the durable mapping and generation checks exist. Use provider object IDs, record request/confirmation separately, and retry bounded observation rather than treating an empty active list as historical settlement.                                                                                                                                            | Unknown ID remains unknown; unrelated objects untouched; termination failure does not claim success; late-created orphan can be found and terminated without reactivating the prompt.                                                                                            |
| Non-creating readiness     | Add an authenticated, bounded endpoint in the create function's deployment surface that validates deployment/image identity, installed SDK and required dependencies without secrets disclosure, sandbox creation or a model call. Plain `api_health` stays liveness-only. Pin/record the remote `function_image` Modal SDK independently of the deploy CLI and test compatibility with the existing investigation network policy.                                | Cold endpoint and dependency failure reported distinctly; missing/mismatched verified image fails closed; no `Sandbox.create`, model request or valid sandbox credential generated by readiness.                                                                                 |

Sequence the work separately: minimal stage telemetry and remote SDK identity verification can
improve the current diagnosis without a new operation service. DIV-84's dispatch fence is the
immediate application repair dependency. The durable-operation mapping/idempotency contract and
interactive provider cleanup capability are broader reliability work requiring their own design
review; they are not prerequisites to documenting or investigating this historical failure. Existing
provider records may settle this incident without implementing that larger contract.

Review durable-operation storage ownership and provider naming/idempotency guarantees before
choosing an implementation. A process-local dictionary is insufficient across function containers,
and simply canceling an asyncio task does not establish rollback of an already-accepted remote
create. Preserve callback payloads privately; repair should use the existing completion machinery
rather than direct DO/D1 SQL edits, index deletion, or an image-build termination endpoint for an
interactive session.

Implement and run focused tests only after the coordinator grants the shared heavy-work slot.
Provider-correlated telemetry may leave the original cause external/unresolved even after these
application guarantees are fixed. Merge, release, any canary and any replacement pilot each remain
outside this proposal's authorization.
